# 주요 기능

## 1. 원클릭 압축

본문을 스캔해 이미지를 자산으로 등록하고 WebP로 변환해 비공개 버킷에 해시 주소로 저장한다. 같은 이미지가 여러 상품에 쓰이면 한 번만 변환(dedup). 변환은 큐(pg-boss) 기반 비동기 — 대량 등록에도 서버가 밀리지 않는다.

## 2. 무오염 서빙 (clean-body)

- 본문 HTML은 영구 원본 — write 경로 자체가 없음
- 스킨 head의 동기 스니펫이 상품 상세 지면에서만 이미지 로드를 선점해 게이트웨이 URL로 교체
- 원본 요청은 전송 전 취소(실측 0KB) — 전송량은 WebP뿐
- gif/svg 등 제외 형식은 불간섭, 미최적화 이미지는 src를 원본으로 복원해 DOM과 실서빙 일치 유지

## 3. 상태 스위치 롤백

서빙 게이트웨이는 "변환 완료" 상태의 자산만 WebP로 응답하고 나머지는 원본으로 302 폴백. 롤백·재최적화가 **본문 수정 0회, DB 상태 변경만으로 즉시 발효**된다. 운영 중 문제가 생겨도 화면이 깨지는 실패 모드가 없다.

## 4. 드리프트 스캔 (매일)

디자이너의 에디터 교체·삽입을 시스템이 모르는 문제 → 매일 새벽 본문과 장부를 URL로 대조:

- 신규 이미지 → 자동 등록·압축
- 위치 이동 → 재매핑·재바인딩
- 사라진 이미지 → orphan 소프트 마킹 (제자리 교체 시 유니크 충돌을 피하는 톰스톤 처리)

## 5. ETag 스윕 (매일 순환)

URL은 같은데 내용만 바뀌는 FTP 덮어쓰기를 CDN ETag(=콘텐츠 MD5)로 감지해 재압축. URL 식별의 사각지대를 내용 지문으로 보완한다.

## 6. 스니펫 3계층 가드 + 워치독

단일 소스 주입(스킨 저장소) → 배포 게이트(누락 시 배포 중단) → 라이브 워치독(매일 PC·모바일 UA로 실페이지 마커 검사). 전 몰이 반응형 단일 스킨이라 파이프라인 배포가 모바일까지 커버하고, 워치독은 에디터 직접 편집·리뉴얼 경로를 잡는다.

## 7. 자가 복구 — 고아 작업 회수

워커가 죽으면(OOM 등) "변환 중" 상태로 잔류하는 작업이 생긴다 → 리퍼(reaper)가 주기적으로 회수해 재큐잉. 처리할 게 없어도 로그 1줄을 남겨 **"조용함 = 정상"을 보장** — 무소음 실패 금지 원칙의 적용.

## 8. 관리자 대시보드

몰별 최적화 현황·절감량·드리프트 이력·실패 자산을 한 화면에서 확인, 재압축·롤백 수동 제어.
