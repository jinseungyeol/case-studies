# 기술적 문제 해결 사례

## 1. 신청 데이터 1,849건 무손실 마이그레이션

- **상황**: 단일 홈쇼핑 채널 전제로 만들어진 신청 시스템에 신규 채널을 추가해야 함. 기존 신청 1,849건은 채널 개념 없이 쌓여 있었음
- **접근**: 채널·차수를 1급 엔티티로 승격하는 스키마 확장 + 기존 데이터를 기본 채널로 귀속시키는 마이그레이션. 건수 대조로 무손실 검증
- **결과**: 이후 채널 추가는 데이터 행 추가로 해결 — 같은 문제가 재발하지 않는 구조로 종결

## 2. 방문자 통계의 중복 부풀림

- **증상**: 새로고침·재방문이 방문 수를 부풀림
- **해결**: 집계 시점에 걸러내는 로직 대신 **IP+시간 단위 유니크 제약**을 DB에 둠 — 중복 삽입 자체가 실패하므로 애플리케이션 로직의 누락·경합에 영향받지 않음

## 3. 개발 중 운영 DB 오염 위험

- **상황**: 소규모 팀에서 로컬 개발과 운영 DB 설정이 섞이면 사고가 남
- **해결**: 환경 변수 하나로 로컬은 빈 SQLite 구동. 운영 자격증명이 로컬 기본 설정에 존재하지 않아 실수 경로 원천 차단

## 4. 회차 운영의 수작업 제거

- **증상**: 방송 일정마다 신청 폼 오픈·마감을 코드 수정으로 처리하는 반복 작업
- **해결**: 신청 가능 차수를 허용 리스트로 분리 — 운영 변경이 배포 없이 설정 한 줄로
