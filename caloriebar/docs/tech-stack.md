# 기술스택과 선택 이유

| 기술 | 역할 | 선택 이유 |
|---|---|---|
| Django | 웹 프레임워크 | 관리자 페이지·ORM·미들웨어·인증이 내장 — 소규모 팀이 고객 홈페이지와 백오피스를 한 코드베이스에서 운영하기에 적합. 특히 백오피스 상당 부분을 Django admin 확장으로 해결 |
| MySQL | 운영 DB | 유니크 제약(방문자 dedup·중복 신청 방지)을 DB 수준에서 활용 |
| SQLite | 로컬 개발 DB | 환경 변수 하나로 빈 SQLite 구동 — 운영 데이터에 닿을 수 없는 개발 환경을 제로 셋업으로 제공 |
| HTML/CSS/JavaScript | 프론트 | 고객 랜딩·홈페이지·백오피스 화면. 프레임워크 없이 서버 렌더링 + 바닐라 JS로 유지보수 단순화 |
| 엑셀 내보내기 | 데이터 내보내기 | 운영팀의 실제 소비 형태(엑셀)에 맞춤, 권한별 필터링 적용 |

## 설계 기준

1. **운영팀이 쓰는 도구에 맞춘다** — 통계는 관리자 페이지, 내보내기는 엑셀. 개발자용 도구를 강요하지 않음
2. **제약은 DB에** — dedup·중복 방지를 애플리케이션 로직이 아니라 유니크 제약으로 보장
3. **실수할 수 없는 개발 환경** — 운영 DB 보호를 규칙이 아니라 환경 분리 구조로
