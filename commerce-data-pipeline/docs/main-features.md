# 주요 기능

## 1. 봇 차단과 UI 변화에 견디는 수집

- **실제 브라우저 + 계정별 영속 프로필**: 세션과 신뢰 쿠키를 누적 재사용, 로그인은 만료 시에만
- **사람 유사 입력**: 타이핑과 클릭 패턴을 사람처럼
- **텍스트와 구조 기반 셀렉터**: 해시 클래스 대신 라벨 텍스트로 요소를 찾고, 컬럼은 위치가 아니라 **헤더 텍스트 기준 동적 매핑**
- **실패 시 현장 보존**: 실패 순간의 스크린샷, 전체 DOM, 메타(가림 요소 조사, API 응답 상태코드)를 캡처해 진단 근거로 남김

## 2. 다중 적재 (세 경로 분기)

| 경로 | 대상 | 주기 |
|---|---|---|
| Google Sheets | 매출팀 실시간 공유 | 매시간 |
| BigQuery (append-only + CDC) | 전일 확정치 누적 분석 | 매일 새벽 |
| BigQuery intraday | 당일 시간별 스냅샷 | 매시간 통째 교체 |

## 3. 거짓 성공 방지, 적재 전 검증 게이트

"성공처럼 보이는 실패"를 잡는 것이 이 파이프라인의 정체성이다. 수집한 값은 아래 검사를 전부 통과해야 BigQuery로 간다. 하나라도 어긋나면 그날 그 브랜드는 적재하지 않고 Slack으로 사유를 보낸다.

- 화면 요약 카드 대조. 긁어 온 표의 캠페인 합계를 화면 상단 요약 카드의 합계와 맞춰 본다. 광고비는 반드시 일치해야 한다.
- 성과 그래프 대조. 광고센터가 그려 주는 날짜별 성과 그래프의 값과 표의 합계를 원 단위로 맞춰 보고, 캠페인 행 수도 센다.
- 예산 배수 가드. 하루 광고비가 그 캠페인의 하루 예산을 세 배 넘게 넘으면 누적 표를 잘못 읽은 것으로 보고 적재를 막는다. 그래프 대조가 맞은 날은 진짜 지출로 보고 이 검사를 건너뛴다.
- 급락 가드. 전날보다 절반 아래로 떨어지면 의심한다. 전날 광고비가 일정 금액 이상일 때만 보고, 비교 기준은 최근 4주 값으로 잡아 원래 적게 쓰는 브랜드를 잘못 잡지 않게 했다.
- 전날 집계 생성 확인. 어제 날짜 데이터가 쿠팡 쪽에 실제로 만들어졌는지 확인한 뒤에만 적재한다. 아직 없으면 0원을 넣지 않고 그날은 미적재로 표시한다.
- 페이지 누락 검사. 표가 여러 페이지로 나뉘어도 행 수를 세어 뒷페이지가 빠지지 않았는지 확인한다.
- 같은 이름 캠페인 분리. 이름이 같은 캠페인이 둘이면 상태와 캠페인 ID까지 키에 넣어 하나로 합쳐지지 않게 한다.
- 오래된 값 차단. 이전 값과 똑같은 채로 갱신 시각만 흐르는 경우를 잡는다.

## 3-1. 늦게 확정되는 값 반영

광고 전환 매출은 며칠 뒤에야 확정된다. 그래서 매일 최근 7일치를 다시 넣어서, 어제의 잠정값이 나중에 확정값으로 바뀌게 했다. 하류에서는 같은 날짜의 가장 최근 값만 쓴다.

## 4. 두 층의 Slack 알림 + 아침 리포트

실행 실패 요약과 적재값 이상 다이제스트를 분리 운영하고, 전날 수집 결과는 매일 아침 Slack 리포트로 자동 보고한다.

## 5. 운영 스위치

운영 중 진단과 복구를 위한 플래그를 처음부터 설계에 포함:

- 한 브랜드만 실행 (문제 브랜드 격리 진단)
- `--cdc N`: 최근 N일 재적재 (전환 정산 보정)
- `--dry-run`: 적재 없이 로직만 검증
- `--no-stage`: 재수집 없이 기존 수집분으로 검증과 적재만 (수집과 적재의 분리)

## 6. 중간 산출물(staging) 계층

수집 결과를 곧바로 적재하지 않고 로컬 JSON(staging)에 먼저 쓴다. 덕분에:

- 적재 실패 시 **재수집 없이** staging에서 재적재 가능
- 검증 로직이 수집과 독립적으로 staging을 대조 가능

## 7. 운영 장애 대응

운영 중 수집이 멈춘 문제는 원인을 찾아 고친 뒤 같은 유형이 다시 막히지 않게 코드에 반영했다. 대표 사례는 [troubleshooting.md](./troubleshooting.md)에 있다.

- 팝업이 버튼을 가림. 프로모션 안내, 광고비 미납 안내, 광고 노출 제한 같은 팝업이 날짜 필터나 달력을 덮어 클릭이 실패했다. 화면을 실제로 덮는 팝업만 골라 닫고, 날짜 필터는 URL로 바로 넘어가게 바꿨다.
- 화면이 다른 곳으로 넘어감. 로그인 뒤 리다이렉트 경로가 계정마다 달라지고, 메뉴가 사라져 다른 화면으로 튕기는 일이 있었다. 목적 화면으로 명시적으로 다시 이동하도록 했다.
- 크롬 업데이트로 로그인 쿠키가 지워짐. 크롬 155와 자동화 도구의 조합이 인증 쿠키를 지워 모든 계정 로그인이 실패했다. 시스템 크롬 대신 번들 브라우저를 쓰도록 바꿨다.
- 다운로드 방식이 바뀜. 매출 엑셀이 어느 날부터 팝업 창으로 내려오기 시작했다. 브라우저 전체의 다운로드 이벤트를 감시하는 방식으로 바꿨다.
- 화면 초기화가 멈춤. 봇 차단이 아니라 앱 초기화가 멈춘 경우가 있었다. API 응답 코드를 기록해 둘을 구분하고, 세션 저장소를 비운 뒤 처음부터 다시 들어가는 복구 단계를 넣었다.
