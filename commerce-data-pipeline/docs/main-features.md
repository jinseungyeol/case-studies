# 주요 기능

## 1. 봇 차단·UI 변화에 견디는 수집

- **실제 브라우저 + 계정별 영속 프로필** — 세션·신뢰 쿠키를 누적 재사용, 로그인은 만료 시에만
- **사람 유사 입력** — 타이핑·클릭 패턴을 사람처럼
- **텍스트·구조 기반 셀렉터** — 해시 클래스 대신 라벨 텍스트로 요소를 찾고, 컬럼은 위치가 아니라 **헤더 텍스트 기준 동적 매핑**
- **실패 시 현장 보존** — 실패 순간의 스크린샷·전체 DOM·메타(가림 요소 조사, API 응답 상태코드)를 캡처해 진단 근거로 남김

## 2. 다중 적재 (세 경로 분기)

| 경로 | 대상 | 주기 |
|---|---|---|
| Google Sheets | 매출팀 실시간 공유 | 매시간 |
| BigQuery (append-only + CDC) | 전일 확정치 누적 분석 | 매일 새벽 |
| BigQuery intraday | 당일 시간별 스냅샷 | 매시간 통째 교체 |

## 3. 거짓 성공 방지 — 다층 검증

"성공처럼 보이는 실패"를 잡는 것이 이 파이프라인의 정체성:

- **화면 요약 대조** — 수집한 셀 값의 합계를 화면의 요약 수치와 대조
- **이상값 검출** — 급락·브랜드 누락·파싱 의심 패턴 감지
- **스테일 차단** — 이전 값과 동일한 채로 갱신 시각만 흐르는 경우 감지
- **fail-closed 게이트** — 예산 대비 비정상 배수 등 불변식 위반 시 적재 자체를 차단

## 4. 두 층의 Slack 알림 + 자동진단

실행 실패 요약과 적재값 이상 다이제스트를 분리 운영하고, 실패 알림은 [자동진단 봇](./auto-diagnosis-bot.md)이 받아 원인 분석까지 수행한다.

## 5. 운영 스위치

운영 중 진단·복구를 위한 플래그를 처음부터 설계에 포함:

- 한 브랜드만 실행 (문제 브랜드 격리 진단)
- `--cdc N` — 최근 N일 재적재 (전환 정산 보정)
- `--dry-run` — 적재 없이 로직만 검증
- `--no-stage` — 재수집 없이 기존 수집분으로 검증·적재만 (수집과 적재의 분리)

## 6. 중간 산출물(staging) 계층

수집 결과를 곧바로 적재하지 않고 로컬 JSON(staging)에 먼저 쓴다. 덕분에:

- 적재 실패 시 **재수집 없이** staging에서 재적재 가능
- 검증 로직이 수집과 독립적으로 staging을 대조 가능
- 자동진단 봇이 실패 시점의 데이터 상태를 그대로 조사 가능
