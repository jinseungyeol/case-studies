# 기술적 문제 해결 사례

## 1. "자동화에서만 나는 시스템 에러", 원인 3분류 물증 확보

- **증상**: 같은 화면을 사람이 열면 정상인데 자동화에서만 시스템 에러
- **접근**: 추측 대신 실패 시점에 **데이터 API의 응답 상태코드를 로깅**하도록 계측 추가. 403/401이면 봇 차단이나 권한, 5xx면 상대 서버, 전부 200인데 화면만 에러면 앱/렌더 문제로 **원인을 셋으로 갈라 물증으로 판정**
- **결과**: "봇 차단인 것 같다"는 추측 대신 케이스별 정확한 대응(세션 복구 / 대기 후 재시도 / 렌더 우회)이 가능해짐

## 2. 날짜 필터를 덮는 프로모션 팝업 (오클루전)

- **증상**: 특정 브랜드에서만 날짜 버튼 클릭이 타임아웃
- **원인**: 새로 뜬 프로모션 오버레이가 날짜 필터를 덮고 있었음. role 속성도 없는 비표준 팝업이라 일반 dismiss 로직에 안 걸림
- **해결**: ①텍스트와 클래스 기반으로 팝업 dismiss + z-index 높은 dim 요소 일괄 정리 ②클릭 대상을 덮은 요소의 tag, class, outerHTML을 실패 메타에 자동 기록하는 **가림 요소 조사(occluder probe)** 를 계측에 추가 ③최종적으로 날짜 필터 자체를 URL 파라미터로 우회해 팝업 의존성 제거

## 3. 여러 날짜 배치가 통째로 사라지는 dedup 버그

- **증상**: 여러 날짜를 한 번에 수집하면 일부 날짜 행이 적재에서 누락
- **원인**: 중복 제거 키에 날짜가 빠져 있어, 다른 날짜의 같은 캠페인 행을 "중복"으로 오판해 버림. 별개로 달력 위젯이 **숨겨진 셀**을 잡아 엉뚱한 날짜를 고르는 버그도 동시 발견
- **해결**: dedup 키에 날짜 포함 + 달력은 보이는 셀만 선택하도록 수정. 복구는 재수집 없이 staging JSON에서 재적재. staging 계층을 둔 설계가 복구 비용을 낮춘 사례

## 4. 같은 이름의 캠페인 쌍이 중복으로 오인됨

- **증상**: 특정 브랜드의 일부 캠페인이 항상 누락
- **원인**: 이름만으로 중복을 판정해, 이름이 같고 대상이 다른 캠페인 쌍 중 하나를 "재읽음"으로 버리고 있었음
- **해결**: 중복 키를 (이름, 아이콘/대상 식별자) 복합키로 변경. 사용자 화면 검증으로 근본 원인을 확정한 뒤 수정

## 5. UI 개편으로 다운로드 메뉴가 조용히 바뀜

- **증상**: 어느 날부터 매출 리포트 다운로드 실패
- **원인**: 채널 프론트 개편으로 메뉴 항목 명칭 변경
- **해결**: 항목을 인덱스가 아닌 텍스트로 찾도록 수정.

## 6. Windows cp949 인코딩 크래시

- **증상**: 한글 로그와 데이터 파일을 읽다가 간헐적 크래시
- **원인**: 인코딩 명시 없이 저장하면 Windows 기본(cp949)으로 쓰이고, 다른 곳에서 utf-8로 읽다 실패
- **해결**: 모든 파일 IO에 `encoding="utf-8"` 명시 + 읽기 루프는 손상 파일 하나에 전체가 죽지 않게 스킵. 배치 파일은 cmd 파싱 사고를 피해 순수 ASCII로 유지

## 7. 사고 후 데이터 복구, 재수집 없는 재적재

- **증상**: 버그 기간 동안 오염된 brand-day 데이터 다수
- **접근**: append-only 구조 덕에 원본은 보존됨. 오염 구간을 특정하고 staging에서 해당 구간만 재적재(re-promote). 이중 집계가 의심되는 곳은 0을 명시적으로 append해(zero-append) 하류 수렴으로 정정
- **교훈**: "지우고 다시"가 아니라 "새 세대를 얹어 수렴"이 복구를 안전하게 만든다

## 8. 새벽에 0원이 적재된 사고

- 증상: 새벽 배치가 어제 광고비를 전부 0원으로 넣었다. 실행 자체는 성공으로 끝나 아무도 몰랐다.
- 원인: 쿠팡 쪽 어제 집계가 아직 만들어지기 전에 화면을 읽었다. 빈 화면을 정상으로 판정한 것이다.
- 해결: 어제 데이터가 실제로 있는지 광고비가 0보다 큰지로 판정하고, 그래프 대조를 필수로 넣었다. 아침 리포트도 실행 시각이 아니라 BigQuery에 실제로 들어간 값으로 판정하게 바꿨다.

## 9. 뒷페이지가 조용히 사라짐

- 증상: 캠페인이 많은 브랜드에서 일부 캠페인이 적재에서 빠졌다. 에러는 없었다.
- 원인: 표가 여러 페이지로 나뉠 때 0행 페이지를 끝으로 오인해 뒷페이지를 읽지 않았다.
- 해결: 0행 페이지를 만나면 빈 표 상태인지 먼저 확인하고, 행 수 검사를 강화해 페이지 유실을 적재 전에 잡게 했다.

## 10. 가짜 급락 경보

- 증상: 급락 알림이 왔는데 실제 광고비는 정상이었다.
- 원인: 하루치만 넣는 가벼운 배치와 7일치를 넣는 본 배치가 같은 비교 기준을 공유해, 총액이 다른 두 배치를 서로 비교하고 있었다.
- 해결: 배치마다 비교 기준을 따로 두고, 하루치 배치는 급락 판정을 건너뛰게 했다.

## 11. 크롬 업데이트로 로그인이 전부 실패

- 증상: 어느 날부터 모든 계정의 로그인이 실패했다. 코드 변경은 없었다.
- 원인: 크롬 155와 자동화 도구의 조합이 인증 쿠키를 지우고 있었다.
- 해결: 시스템 크롬 대신 자동화 도구에 번들된 브라우저를 쓰도록 바꿨다. 영속 프로필은 그대로 유지된다.
